## 📝 專案簡介
**NEXT-TETRIS UNIVERSE** 是一款基於現代網頁全端技術打造的「街機電競風」俄羅斯方塊遊戲。本專案打破傳統單機遊戲的限制，整合了獨立的後端 Server API，提供實時的**全網公開排行榜**與**會員帳號系統**。外觀採用極致暗黑的電競霓虹視覺，並加入硬核玩家必備的影子落點預測、連擊 Combo 浮空特效與多主題即時切換功能，兼具極佳的操作反饋感與全端技術應用價值。

---

## 💡 開發動機
1. **擺脫傳統腳本限制**：挑戰在不使用 Python 的情況下，利用現代全端 JavaScript/TypeScript 生態圈（Node.js 環境）實現完整的遊戲引擎與伺服器邏輯。
2. **實踐全端架構串接**：透過單一網頁框架（Next.js）同時處理前端複雜的 Grid 遊戲渲染，以及後端的 RESTful API 路由、會員驗證（Auth）與資料庫持久化設計。
3. **極致化街機操作體驗**：不滿足於市面上陽春的方塊範例，希望將現代俄羅斯方塊大賽（如 CTWC）中的核心機制（如 Ghost Piece、Combo 乘數、消行特效）重現在自研專案中。

---

## 🏗️ 技術架構
本專案採用 **Next.js (App Router)** 作為核心全端開發框架，全面採用 TypeScript 確保型別安全，並使用 Tailwind CSS 打造響應式電競風介面：

* **前端技術 (Frontend)**：
  * **React 18 Hooks**：利用 `useState`、`useEffect`、`useCallback` 維持高頻率的網格狀態與鍵盤監聽。
  * **Custom Hooks**：封裝 `useInterval` 建立精確、不因 React 重新渲染而卡頓的遊戲核心計時器。
  * **Lucide React**：用於排行榜（Trophy）與主題切換（Palette）的向量圖標。
* **後端技術 (Backend Server)**：
  * **Next.js API Routes**：建立獨立的 Node.js 後端端點，處理 `/api/auth` 驗證與 `/api/leaderboard` 分數讀寫。
  * **檔案系統持久化 (JSON DB)**：利用 Node.js 內建的 `fs` (File System) 模組與 `path` 模組，將資料庫固化為實體 `db.json` 檔案。

## 🎮 核心功能
1. **🔒 完整會員身分系統**：具備「註冊、登入、登出」功能。註冊時後端自動檢查重複帳號並回傳狀態。登入後前端透過 `localStorage` 保持工作階段，登出時清除。
2. **🏆 雲端同步公開排行榜**：當玩家處於已登入狀態下結束遊戲，分數會自動經由後端 API 比對。排行榜採取**「一人一卡、只保留最高分」**機制防止洗板，並在前端對目前登入的玩家名次給予青色高亮標記。
3. **🚀 智慧型影子方塊 (Ghost Piece)**：在棋盤最底部實時渲染一個半透明、帶有虛線邊框的落點影子，且影子顏色會自動跟隨當前操作方塊的主色（如 I 條為青色、T 型為紫色），大幅提升高速盲打時的精準度。
4. **💥 街機風消行 Combo 特效**：
  * **連擊計算**：連續落地消行會不斷累積 Combo 乘數並給予分數加成，中斷則歸零。
  * **浮空字體與畫面閃爍**：一次消除 2 行以上或觸發 Combo時，畫面中央會跳出向上飄移並逐漸淡出的動態特效字（如 `👑 TETRIS! 👑`、`✨ Excellent! ✨`），同時整個棋盤會觸發短暫的黃金霓虹邊框閃爍。
5. **🎨 多主題背景即時切換**：內建主題切換器（Theme Selector），提供「賽博暗黑、霓虹深紫、駭客任務、星際深藍」四款風格，面板外框、網格底色、流光裝飾條皆可一鍵無縫、無閃爍地流暢切換。

## 🧠 開發反思與優化筆記 (核心技術突破)

在本專案的迭代過程中，遇到了數個關乎「遊戲邏輯正確性」、「伺服器穩定度」與「前端動畫流暢度」的關鍵痛點。以下紀錄本人的優化思考與解決方案：

### 1. 觸頂判定（Game Over）邏輯漏洞修復
* **問題根源**：早期版本將 Game Over 條件錯誤地設為方塊固定後的 Y 軸小於 0 (`targetY < 0`)。然而，Next.js 棋盤方塊一開始就是在畫面頂端內部 (`y = 0`) 生成，導致當方塊疊滿觸頂時，遊戲依然不會結束，直接發生畫面卡死狀況。
* **優化方案**：本人主導重新設計判定商務邏輯，改為雙重防護機制：
  1. 當新方塊甫生成於頂端起點時即發生碰撞（代表出生點被卡死）。
  2. 消行結算完畢後，棋盤最頂端（第 0 行）仍有任何殘留的實體方塊細胞 (`filteredGrid[0].some(cell => cell.filled)`)。
  滿足任一條件則立即宣告 Game Over 並結算最新分數，成功修復卡死漏洞。

### 2. 資料庫從記憶體暫存走向檔案持久化（File Persistence）
* **問題根源**：最初為了快速測試，將使用者與排行榜陣列直接開在 JavaScript 全域變數中。這導致 Next.js 在開發期間只要一偵測到原始碼變更觸發「熱重載 (Hot Reload)」，或者是本地伺服器重新啟動，所有已註冊的玩家帳號與歷史排行就會全部蒸發。
* **優化方案**：為了在不引入繁重外部資料庫（如 PostgreSQL）的情況下達到永久儲存，本人提出改用 Node.js 內建的 `fs` (檔案系統) 模組。在伺服器端建立 `db.json` 作為實體資料庫中繼站，利用 `fs.readFileSync` 與 `fs.writeFileSync` 機制，讓任何註冊與高分覆蓋都能立刻同步寫入硬碟，實現了無畏伺服器重啟的永久儲存。

### 3. 排行榜洗板防護與重複名稱處理
* **問題根源**：若不加限制，同一個技術高超的玩家只要連續玩五把，排行榜前五名就會全部被同一個帳號佔據（洗板），這會大幅降低其他玩家註冊與挑戰的樂趣。
* **優化方案**：在 `api/leaderboard/route.ts` 寫入分數時，本案加入了 `findIndex` 名稱不分大小寫比對。若該帳號在 JSON DB 中已存在，則進行分流判斷：只有當次分數「大於」該玩家的歷史最高分時，才會執行資料覆蓋與更新日期；若低於歷史紀錄則直接忽略，達成「一人一卡、只留奇蹟最高分」的公平競爭賽制。

### 4. 連續消行動畫字體卡死與 DOM 刷新優化
* **問題根源**：在 React 中，如果短時間內連續觸發相同的 Combo，由於文字內容（例如：Combo × 1!）或結構極為相似，React 的虛擬 DOM (Virtual DOM) 機制會判定該節點不需重新掛載（Remount），導致浮空飄移的 CSS `keyframes` 動態特效只播了一次就卡住，後續連擊完全沒有動畫反饋。
* **優化方案**：本案在 `effect` 特效狀態中引入了 `Date.now()` 時間戳記，並將其作為該 HTML 特效元素的 `key` 值（`key={effect.id}`）。透過利用 React 的 Key 變更機制，強迫 React 在每一次消行時，都將特效組件視為全新的實體進行重新銷毀與掛載，成功確保每一次 Combo 街機動畫都能百分之百完美重播，大幅提升消行時的爽快打擊感。

### 5. 智慧影子方塊（Ghost Piece）雙層無衝突渲染
* **問題根源**：要在網格最底部顯示一個提示玩家落點的半透明方塊，必須確保它能隨著玩家左右移動或旋轉時即時更新，且不能與當前正在下落的實體方塊產生顏色衝突或閃爍。
* **優化方案**：在 `renderDisplayGrid` 渲染函數中，本人引導設計了「雙層模擬混合演算法」。先複製一份當前固定的棋盤背景，透過 `while` 迴圈不斷向下測試 `checkCollision` 直到撞擊，計算出落點的 `ghostY` 並鋪上標記為 `isGhost: true` 的虛線細胞；接著在相同網格上疊加真實控制中的方塊。當兩者重疊時，以實體方塊樣式覆蓋影子，實現了完全流暢、無延遲且色彩連動的影子投影功能。
